# Finance Tracker

A fullstack personal finance tracker with authentication, transaction management, and an analytics dashboard.

## Tech Stack

- **Frontend** — React 18 + TypeScript, Vite, Tailwind CSS, TanStack Query, Recharts, Lucide
- **Backend** — Node.js, Express 5, TypeScript, Prisma ORM, PostgreSQL, zod
- **Auth** — JWT + bcrypt
- **Deployment** — Render (Web Service for the API + Static Site for the client), Neon for Postgres

## Features

- Email/password auth with hashed passwords, JWT sessions, protected routes
- Dynamic dashboard: balance / income / expense cards with Day/Week/Month/Year selectors and period-over-period % change
- Bar chart: yearly income/expenses/profit broken down by month
- Pie chart: category breakdown filterable by month, year, and type
- Full CRUD: transactions, accounts, categories
- Settings: profile, currency (USD/EUR/etc.), password change, account/category management, account deletion
- Per-account `currentBalance = initialBalance + signed_sum(transactions)` computed on read

## Local development

### 1. Prerequisites

- Node.js 18+
- A PostgreSQL database (local Postgres or a free Neon database)

### 2. Server

```bash
cd server
cp .env.example .env
# Fill in DATABASE_URL and JWT_SECRET in .env
npm install
npx prisma migrate deploy
npm run dev
```

The API will listen on `http://localhost:5000` by default.

### 3. Client

```bash
cd client
cp .env.example .env
# .env defaults to VITE_API_URL=http://localhost:5000
npm install
npm run dev
```

The app will open at `http://localhost:5173`.

## Deploying to Render

The `render.yaml` at the repo root defines both services.

1. **Create a free Neon Postgres database.** Copy the pooled connection string (the one ending in `-pooler.<region>...`).
2. In Render, click **New → Blueprint** and point it at this repo. It will detect `render.yaml` and propose two services.
3. Before the first deploy completes, set the env vars Render flagged as `sync: false`:
   - On `finance-tracker-api`:
     - `DATABASE_URL` = your Neon connection string
     - `CLIENT_URL` = the URL Render assigns the web service (e.g. `https://finance-tracker-web.onrender.com`)
   - On `finance-tracker-web`:
     - `VITE_API_URL` = the URL Render assigns the API service (e.g. `https://finance-tracker-api.onrender.com`)
4. `JWT_SECRET` is auto-generated by Render.
5. The API's `buildCommand` runs `prisma migrate deploy`, so migrations are applied automatically.

After the first deploy succeeds, re-deploy the client once you know the API URL (so the Vite build picks it up). Same the other way around for `CLIENT_URL` on the API.

## API reference

All endpoints except `/auth/register` and `/auth/login` require `Authorization: Bearer <token>`.

| Method | Path                       | Description                                                  |
| ------ | -------------------------- | ------------------------------------------------------------ |
| POST   | `/auth/register`           | Create account, returns `{ token, user }`                    |
| POST   | `/auth/login`              | Returns `{ token, user }`                                    |
| POST   | `/auth/change-password`    | Change current user's password                               |
| GET    | `/users/me`                | Current user                                                 |
| PATCH  | `/users/me`                | Update name / email / currency                               |
| DELETE | `/users/me`                | Permanently delete current user (cascades to all owned data) |
| GET    | `/accounts`                | List accounts (with `currentBalance`)                        |
| POST   | `/accounts`                | Create account                                               |
| PUT    | `/accounts/:id`            | Update account                                               |
| DELETE | `/accounts/:id`            | Delete account (cascades to its transactions)                |
| GET    | `/categories`              | List categories                                              |
| POST   | `/categories`              | Create category                                              |
| PUT    | `/categories/:id`          | Update category                                              |
| DELETE | `/categories/:id`          | Delete category                                              |
| GET    | `/transactions`            | List transactions                                            |
| POST   | `/transactions`            | Create transaction                                           |
| PUT    | `/transactions/:id`        | Update transaction                                           |
| DELETE | `/transactions/:id`        | Delete transaction                                           |
| GET    | `/health`                  | Liveness check                                               |
